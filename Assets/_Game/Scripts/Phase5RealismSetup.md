# Phase 5 — Realism systems

Implements and integrates the core simulation work in timeline sections 5.1–5.6A. Device profiling and the 5.7 acceptance milestone must still be completed in Unity. Section 5.8 explicitly lists optional later work; this change does not add analytics services or expand those optional features.

## Run the combined scene

Open `Assets/_Game/Scenes/RealismTest.unity` by itself in Unity 6000.3.10f1 and press Play. It loads the bundled Nairobi roads, the Phase 2 bus, and the generated three-stop Phase 4 training service. No network token is required. Select **Review training mission → Depart**, then **Open doors** at the first stop. Follow the cyan line and dock at the remaining stops. The last stop is the training depot for refuelling and settlement.

The Phase 5 panel shows actual traffic tiers, occupancy, satisfaction, and brake/axle/engine condition. Weather buttons start 180–300 second transitions. **Day / night** changes the shared schedule clock for lighting checks; doing this during a scored mission also changes its punctuality. **Cabin view** toggles the test bus shell renderer so passenger proxies remain visible. The physical body collider is retained. The fixture uses simple geometry and generated bell/siren tones; these are test assets, not finished bus/passenger art.

## Systems and integration

- PassengerSpawner uses daily density peaks at 07:30 and 17:30, each 5× baseline, including subsequent simulation days. PassengerManager prepares waiting passengers on approach, enforces capacity, removes boarded agents from the waiting queue, and tracks destinations. PassengerVisualPool reuses a bounded set of visible proxies for waiting, boarding, seated/standing, and alighting agents. Standing reactions use physics-step time. Wheelchair chance is 5%, requires kneeling, and adds 10 seconds of dwell. Results retain satisfaction of passengers who have exited. Mission departure waits for both dwell and service animations. At capacity, boarding-only door requests are refused; alighting and terminal evacuation remain possible.
- VehiclePool warms 50 car/truck/motorcycle/emergency instances. Full simulation runs within 200 m, with 25 m promotion/demotion hysteresis and an 18-body default budget. The pool accounts for scheduled buses against a scene-wide 20-body ceiling. Lightweight motion runs out to 400 m; vehicles farther away are inactive. Tier changes preserve the current graph edge, pose, and speed. TrafficParticipant shares headway checks across both tiers and the player bus. Lane offsets are absolute targets, avoiding frame-rate-dependent lateral drift. Passing requires an explicitly multi-lane graph and a clear adjacent lane. The OSM bridge conservatively uses one lane because the current provider-neutral graph does not retain lane counts; production lane permissions must be authored from validated road data.
- RoadTrafficBridge builds AI waypoints from the same directed RoadGraph used by gameplay. Signals are bound to nearby nodes. Generated signal associations and intersection approaches require visual review. PedestrianSpawner reuses crossing pedestrians, admits them while traffic is red, and enforces its configured population cap. Ambulance sirens notify both simulation tiers. Scheduled buses reuse a separate bounded pool, follow fixed node sequences, and join the same distance/budget policy.
- Weather transitions update precipitation and grip continuously. Outgoing precipitation fades out before the incoming state fades in. Night is composable with any weather state. Rain particles follow the bus, with reduced emission and particle limits on Low quality. Wet road renderers use property blocks for darkening and smoothness. The test wiper is procedural; RainController also supports production Animator wiring. FogController provides URP-compatible distance fog with blended visibility; a true volumetric lighting/fog renderer is not supplied. Production weather rendering remains part of visual acceptance.
- RoadSurfaceFrictionController owns composed weather × surface × tyre grip. MaintenanceSystem and WeatherPhysics defer wheel writes when that controller is present, preventing update-order overwrites. Without it, their legacy standalone paths remain available. TimeOfDaySystem shares ScheduleManager's 1× clock and applies daylight-shaped intensity to the sky/sun, street lights, headlights, and cabin lights.
- Fuel retains the 300 L tank, 35/28 L per 100 km city/motorway baseline, RPM/gradient factors, and +18% at full passenger load. Depletion accounting is clamped to actual remaining fuel. The HUD exposes 20%/5% warnings through FuelSystem. Maintenance tracks brake use, axle tyre wear, and elapsed engine hours; stationary braking does not consume brake life. Tyre grip starts degrading beyond 50% wear. Existing mission settlement refuels at a depot and deducts service/refuel costs from earnings; MissionResult persists the breakdown. Production garage UI already exposes the maintenance data.

## Detail and memory controls

VehicleDistanceLod selects full geometry below 100 m, reduced geometry beyond 100 m, and a billboard beyond 300 m, with culling beyond 400 m. The fixture's traffic templates demonstrate these tiers, including its scheduled bus. Assign production model renderers and authored impostor textures to replace the geometric placeholders.

RoadGeometryLod creates reduced ribbon meshes on worker tasks and swaps at most four roads per refresh beyond 500 m. Original road colliders are retained. TileStreamManager separately uses 0–200/200–500/500+ metre detail tiers based on distance to tile bounds, not tile centres, so the tile underneath the bus remains near-detail. The default medium grid has 36% of near-tier polygons (6×6 versus 10×10); the far tier is a flat quad. Only the near tier has tile mesh colliders. In the fixture, OSM roads own collision and raster tile colliders are disabled altogether.

Tile sources are retained as compressed PNG bytes rather than a full-resolution source GPU texture plus decoded pixels. Worker tasks build mesh arrays and downsample texture data; version checks discard stale results. Unity object creation, texture decoding, GPU upload, and collider assignment necessarily stay on the main thread with bounded jobs/applies. Medium/far texture dimensions are halved/quartered and CPU upload copies released. Runtime GPU block compression is not guaranteed on Android; configure/import platform textures separately when that is required. No specific RAM reduction percentage has been measured.

## Stress test and validation

Open `RealismStressTest.unity` on its own to start a light-rain training mission with rush-density boarding intended to fill the 80-passenger bus, then run the benchmark automatically. The ordinary realism scene's **Benchmark** button measures its current state. Both fixtures use a 50-vehicle pool and measure requested counts in steps of five. Actual active counts can be lower as vehicles leave the 400 m range. CSV includes actual full/spline/dormant counts, passenger count, weather, average FPS (frames / elapsed seconds), and p95 frame time. Verify occupancy and active counts in the CSV before accepting a run. Reports are written to `Application.persistentDataPath/traffic-stress-<UTC timestamp>.csv`.
